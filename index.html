Nutrition estimate

Estimated from this recipe's ingredients. Scanned brands win first — if an ingredient matches something in your brand pantry (scanned from its packet), its label values are used and the line says so. Then the built-in table (Indian spices, ghee, ginger-garlic paste, plain Greek yoghurt, plain chicken breast), then USDA FoodData Central for the rest. Other amounts are converted to grams where the database knows the portion, or with a standard tablespoon/teaspoon weight where it doesn't. It's a close estimate, not lab values — branded products vary, which is why your typed-in nutrition always wins unless you save an estimate over it.

The shared demo key is heavily rate-limited. A free personal key takes two minutes: fdc.nal.usda.gov/api-key-signup. Saved on this device only.
Per-serving values and Save need a serving count. If this recipe has none yet, enter it here — saving also sets the recipe's servings, so the detail page shows the servings chip and scaler.

Nothing is saved until you tap “Save estimate to recipe”. Closing this panel with the × or by tapping outside discards the estimate — the recipe is unchanged.

Sync between phone & laptop

Sync keeps the same recipes, cooked history and pantry on both devices. Your recipes still live on this device first and the app works fully offline — sync just copies changes across when you're online.

Saved on this device only, like your USDA key — never in the code or the repo. Supabase dashboard → Settings → API → Project URL + anon public key. Paste the Project URL exactly as https://xxxx.supabase.co — with nothing after it, no /rest/v1, no /auth/v1.
Used only to sign in on this device. It is never stored — only the login session is kept, on this device.

  1. In the Supabase dashboard for the blog project, open SQL Editor and run schema.sql (shipped with this batch). It creates a plateful_sync table with Row Level Security: only your signed-in account can read or write its own rows. No anon access at all.
  2. Authentication → Users → Add user — create your account (email + password), or use your existing blog admin login. There is no public sign-up.
  3. Paste the Project URL + anon key above, on this device, and sign in. Repeat on your other device.
  4. Tap Sync now on the laptop first, then on the phone. After that it syncs by itself when you add, edit, cook or delete a recipe.
Photos sync inside the recipe (no Storage bucket needed). The nutrition cache and your USDA key stay on each device. JSON backup/restore still works as a fallback.

Scan a barcode

Scan a packet and add it to your pantry in one step — your nickname for it, how much, and its use-by date, with the label nutrition attached. When a recipe uses that packet, the estimator uses its label numbers — pantry item > scanned brand > built-in table > USDA.

Open Food Facts is crowdsourced — strongest in France/Europe, thinner for US and Indian items, and some packets simply aren't in it yet. Data can be incomplete or out of date; the label wins, especially for allergens.

Works without a camera — typing the digits runs the same lookup and save flow.
Camera needs the scanner library (loaded on demand from jsDelivr) and camera permission. If either fails, typing the barcode above still works.
